# 诊断：v2 为什么读起来不像协议

> 依据：`PROTOCOL.md`（v2.0，475 行）与归档的 v1 协议（`PROTOCOL-v1-historical.md`，705 行，见提交 `14e77f1^`），以及更早的三分册规范（`antlegion-bus/protocol/{SPEC,EXTENSIONS,IMPLEMENTATION-NOTES}.md`，见 `542dac9`）。

## 结论先说

**v2 不是"更简洁"，是丢了规范的骨架。**

v2 的设计确实比 v1 简单得多——总线从"带两个状态机的仲裁者"缩成了"只发号的日志"。但文档把**实现变简单**误当成了**规范可以少写**。这是两件事：协议的严谨性不来自实现有多复杂，而来自**定义有多完备**。一个只有两个操作的协议，同样需要术语表、需要逐操作时序、需要状态转移表、需要说清楚哪些是强制哪些是推荐。

结果是：v2 读起来像一篇主张（"一个本原、两个操作、其余皆推论"），而不像一份可据以实现的规范。**一个第三方拿着 v2 去写一个兼容实现，会在十几个地方卡住并被迫猜测。**

## 逐项对照

| v1 有的规范部件 | v1 位置 | v2 |
|---|---|---|
| **实体定义**（Fact / Ant / Acceptance Filter / Bus 各自正式定义） | §2 Protocol Entities | ❌ 无。v2 直接用这些词，从不定义 |
| **字段分组**：Immutable Record Fields / Mutable Bus State Fields | §2.1 | ❌ 平铺成一个 JSON 块，靠注释区分 |
| **操作目录**（Operation Catalog） | §6.1 | ❌ 无 |
| **逐操作时序**（PUBLISH / CLAIM / RESOLVE / CORROBORATE 各一节） | §6.2–§6.5 | ❌ 无。只有 HTTP 端点，没有"一次完整交互按什么顺序发生" |

## 三个最伤的缺口

### 一、没有系统模型

协议的全部价值在于**说清楚主张在什么条件下成立**。v2 通篇断言"恰好一次""确定性""崩溃可恢复"，却从未集中声明：

- 谁可信？（总线的哪些字段可信、作者的哪些字段不可信）
- 假设什么故障？（进程崩溃？网络分区？拜占庭作者？磁盘损坏？）
- **不**假设什么？（比如：不假设时钟同步，不假设作者诚实，但假设总线诚实且单点）
- 多个总线怎么办？（现在只字未提，而这直接决定"全序"的适用范围）

没有这一节，读者无法判断这些保证在自己的部署下还成不成立。

### 二、"定理"没有证明

v2 最核心的主张是：

> 恰好一次分配是全序的一条数学定理：`claim_of` 中 `seq` 最小的获胜。

这句话在 v2 里出现了至少四次，**每次都是断言**。而一份协议应当给出：

- **定理陈述**：形式化的前提与结论
- **证明**：为什么每个读者必然算出同一个赢家
- **前提的暴露**：这个证明依赖哪些假设（全序唯一、记录不可变、折叠函数纯、读者最终读到相同前缀……）
- **边界**：什么情况下不成立（例如读者读到的前缀不同——那结论是"最终一致"还是"当下一致"？v2 没说）

最后一条尤其要命：**两个读者在不同时刻读，看到的流长度不同，凭什么保证结论一致？** 这需要一个"结论一旦确定就不再翻转"的单调性论证。v2 里没有，而这是整个设计能否成立的关键。

### 三、没有逐操作时序

v1 的 §6.3 CLAIM Sequence 会告诉你：客户端发什么、总线做什么检查、返回什么、失败时怎么办、然后客户端该做什么。v2 只给了 `POST /facts` 和 `GET /facts`，然后说"其余是折叠"。

但对实现者来说，**"我要领一件活"这个动作到底要发几个请求、按什么顺序、怎么确认自己赢了**——这是必须写清楚的。现在它散落在 §3.1 的折叠规则里，需要读者自己拼。

## 但 v1 也不值得照抄

v1 的**体例**值得学，**内容组织**不值得：

- v1 有 `Mutable Bus State Fields`——这正是 v2 要消灭的东西。字段分组的**形式**要保留，但 v2 的分组依据不同（作者域 vs 总线域，而非不可变 vs 可变）。
- v1 的状态机是**服务端**状态机；v2 没有服务端状态机，但**折叠有状态转移**，仍然需要一张转移表，只是它规范的是读者而非总线。
- v1 §1.2「The AI Matrix Thesis」这类哲学章节，是文档抽象化的起点。v2 把哲学从 §1 挪到了 §0，但没删——反而因为规范部分变薄，哲学占比更高了。**哲学应该压缩进引言，不该占据规范正文。**

## 该怎么改

见 [03-spec-skeleton.md](03-spec-skeleton.md)。一句话概括：**保留 v2 的设计，恢复 v1 的体例，再补上 v1 也没有的系统模型与证明。**
