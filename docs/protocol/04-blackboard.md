# 定位：黑板架构在自治智能体时代的重做

> 用途：统一 README 与官网的叙事，并为 `PROTOCOL.md` 的引言与「相关工作」一节提供素材。

## 现状：叙事是断的

`site/index.html` 首屏用的是黑板叙事，而且已经找到了最锋利的那一句：

> 黑板架构比万维网还老——它一直没解干净的问题是「谁来仲裁」。AntLegion 的回答：行号来仲裁。

而 `README.md` 讲的是「fact bus / 只有事实没有命令」，**全文没有出现"黑板"二字**。两个入口，两套故事，互不引用。`package.json` 的 keywords 里躺着 `blackboard`、`stigmergy`、`tuple-space`，但仓库里没有任何一处解释过它们的关系。

要补的不是发明一套说法，是**把已有的那套接回来**。

> **定位修正（2026-08-19）。** 项目定位已定为**给智能体共享世界状态的事实日志**，品牌隐喻
> 是**蚂蚁读地面上的信息素**（stigmergy）。黑板架构立得住，正因为黑板首先是**共享世界状态**
> 的介质——知识源往上写的是对世界的观察，而不是给谁的指令；「谁来仲裁领活」只是黑板上
> 一种特殊的世界状态（所有权）如何保持唯一的问题。下文把仲裁讲成要害是对的，但要害的
> *上位*是「板子本身就是世界」，先讲这个，再讲仲裁。对外文案不得把黑板讲成「多智能体协作」。

## 核心说法

> **AntLegion 是黑板架构在自治智能体时代的重做：保留「一块所有人写观察、没有人被寻址」的共享世界，删掉中央控制器，用一条全序让每个读者算出同一个世界——包括「谁拥有什么」这块世界，于是「谁来仲裁」从调度问题变成算术问题。**

一句话版本（可作 README 副标题）：

> **给 AI 智能体的黑板——只不过每一行都有编号，而行号就是仲裁者。**

## 为什么这个说法立得住

经典黑板架构（Hearsay-II，1970 年代）三个部件，逐一对照：

| 经典黑板 | 是什么 | AntLegion |
|---|---|---|
| **Blackboard** | 共享数据结构，所有知识源可读写 | 只追加的事实日志——但**不可变**，只增不改 |
| **Knowledge Sources** | 独立专家模块，各自盯着黑板，条件满足即贡献 | DCU / 任意智能体，各自折叠事实流，触发谓词成立即领活 |
| **Control Component** | 调度器，决定下一个激活谁 | **删除** |

**第三行是全部要害。**

经典黑板五十年来最被诟病的就是这个控制组件：它是中心化点、是瓶颈、是必须有人维护的调度策略——而且它一旦存在，"知识源自主贡献"就是假的，真正做决定的是调度器。

AntLegion 的替代方案不是"更好的调度器"，而是**取消调度这个动作**：

1. 领活本身就是往黑板上写一行（`_.claim`）
2. 全序保证每行有唯一编号
3. **编号最小的领活获胜**——这不是一条规则，是从全序推出的结论
4. 每个读者独立计算，必然得出同一个赢家；无需任何人被通知

于是「谁来仲裁」的答案是：**没有人。算术在仲裁。**

> 这一条与[推导](02-derivation.md)第 3 步是同一件事：那张表里被否掉的"中央调度器分派"，正是经典黑板的控制组件。两条线在此汇合。

## 三个可以说得更强的点

### 一、这不是复古，是补上了当年缺的那块

经典黑板依赖**集中式序列化**来避免读写冲突——而那恰恰是它没做好、在分布式环境下也做不好的部分。AntLegion 把全序做成了唯一的、也是仅有的服务端职责：总线只干一件事——发号；除此之外不持有任何状态。

**缺的那块补上了（可信的全序），多余的那块删掉了（控制器）。**

### 二、黑板正在为 LLM 时代复兴，且有数据

2025 年的工作把黑板架构重新用于 LLM 多智能体：智能体自愿响应而非被指派，明确对标 master-slave 式任务分配，效果高出 **13–57%**（[arXiv:2510.01285](https://arxiv.org/abs/2510.01285)）。另有工作指出，黑板系统历来"使用集中式序列化"，而这正是 AntLegion 所依赖、并且做成了唯一服务端职责的东西（[arXiv:2510.18893](https://arxiv.org/abs/2510.18893)）。

定位不是怀旧，而是踩在一条正在回暖的线上——并且是这条线上少数**把仲裁真正解决掉**的实现。

> 出处见 `research/ecosystem-gtm-report-2026-07.md`。引用进对外文档前应复核原文结论与口径。

### 三、"facts, not commands" 与黑板是同一件事的两种说法

黑板上只能写"发生了什么"，不能写"你去做什么"——因为**黑板没有收件人**，写给谁看是读者自己决定的。

现有公理不需要改口径，它本来就是黑板纪律的严格化。
