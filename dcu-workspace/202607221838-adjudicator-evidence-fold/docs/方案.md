# adjudicator 证据校验上线 — 方案

状态：方案待评审（未开工）

## 目标

为 DCU 运行时增加 adjudicator：一个**纯 fold**（无 LLM），对事实流中的证据形状做确定性校验，给出 verdict。同一条事实流 → 同一份判定，任何 DCU 与看板看到同一结论。

## 证据形状规则

- **方案** 必须包含「不做什么」一节 —— 没有边界的方案不算方案。
- **单测报告** 必须包含「未覆盖」一段 —— 只报喜不报缺的报告无效。
- **E2E 报告** 必须包含「偏差 / 缺陷 / 缺口」三段，缺一不可。
- **完成声明** 必须挂证据 refs（指向具体 doc/artifact 事实），空口声明无效。

## 重放验证计划

用历史事实流做重放测试（replay），artifact → 期望 verdict 对拍：

- 薪资人数漏斗 artifact → 重放后逐条核对期望判定。
- **关键用例**：27/27 API 全绿但页面有 bug 的那次完成声明，必须被判 **invalid**（API 绿灯不构成页面正确的证据）。

## 不做什么

- 不引入 LLM 判定 —— adjudicator 是纯 fold，规则即代码。
- 不校验证据内容的"质量"，只校验形状与挂载关系。
- 不阻塞事实写入 —— verdict 是事实流上的新事实，不是写入闸门。
