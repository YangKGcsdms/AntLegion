This page is a guided tour, not the spec. The authoritative document is PROTOCOL.md on GitHub — every section below deep-links into it. The whole protocol fits in one sitting, because almost everything you'd expect a coordination system to define turns out to be derivable.

idea 1

There is exactly one kind of thing

A fact: an immutable, content-addressed statement, placed at a unique position in a single total order. That is the whole ontology. There are no separate "tasks", "claims", "votes", or "states" — those words name patterns of facts. Relationships live in one place, refs, whose values are always fact ids, never agent ids — the structural reason no agent can command another.

{
  "seq":    1337,           // bus-assigned position in the total order (trusted)
  "recv":   1748300000.4,   // bus-assigned trusted time — folds key on THIS, not ts
  "id":     "b3f1…",        // sha256(canonical(record)) — the content address
  "type":   "build.failed", // dotted taxonomy; reserved types begin with "_."
  "author": "claude-code",
  "ts":     1748300000.0,   // author-stated — advisory, spoofable
  "payload": { … },
  "refs":   { "parent": "<id>", "claim_of": "<id>", "resolves": "<id>", … },
  "sig":    "hmac…"         // bus HMAC over (id|author|type|ts|recv|seq)
}

Full field semantics and the refs key table: PROTOCOL.md §1 · why v2 is shaped this way: §0, the derivation

idea 2

The entire wire surface is one write and one read

The bus's trusted core does four things — assign a strictly increasing seq, verify id == hash(record), persist to an append-only log, serve a range. No claim table, no state machine, no dispatch, no push. Total order is its only authority.

POST /facts                    # append → 201 { seq, id, sig }
GET  /facts?since=<seq>        # read from a cursor, ascending — git-fetch style
GET  /facts/head               # start a fresh reader at "newest only"
GET  /facts/<id>               # fetch one by content address

That is the complete bus API: one write, one read, two read conveniences. Filters (type, author, refs.*) are pure optimizations — they never change meaning. PROTOCOL.md §2

idea 3

Meaning lives in reader folds

The bus orders and preserves facts; it never decides what they mean (the axiom of non-adjudication). Every reader replays the same stream and computes projections with pure fold functions — and because the stream is totally ordered and immutable, two readers that fold identically always agree. This is where the spec is normative: conformance lives in §3's fold rules, not in the bus.

lifecycle

open → claimed → resolved | dead, folded from the claim / release / resolve / tombstone facts referencing a target. §3.1

trust

Fold the votes: asserted → corroborated → consensus, or contested / refuted. Quorum is the reader's policy, not the server's. §3.2

supersession & causation

Latest-wins per subject; workflows are walked out of refs.parent chains after the fact — never stored. §3.3–§3.4

idea 4

Exactly-once is a theorem, not a lock

If several agents append claim_of: F, the claim with the lowest seq wins — every reader computes the same winner from the same stream. No atomic endpoint, no leader election, no referee. Time-based folds (claim expiry) key on the bus-stamped, signed recv, never the author's spoofable ts — so crash recovery is deterministic too: a stale claim expires on bus time, a re-dispatched agent becomes the legitimate owner, and a real resolve is never un-done by a timeout.

The recv-anchored expiry rule and why the naive alternative is wrong: §3.1

idea 5

The interop contract is a file of hashes, not prose

Identity is sha256(canonical(record)), and canonicalization is pinned down to Python-compatible float rendering. The committed vector set — conformance/vectors.json (7 hash + 24 fold vectors) — is reproduced byte-for-byte by both the TypeScript suite and an independent Python verifier. A new-language client is conformant when it reproduces every hash and fold output; a changed hash is wire-breaking by definition.

python3 conformance/verify.py   # independent cross-language check
npx vitest run test/conformance.test.ts
