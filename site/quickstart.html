step 1

Start the bus — pick any of three

The bus is one process with one job: number every fact and never erase. All three channels run the same thing on localhost:28090.

npx — fastest

npx @antlegion/bus
# append-only fact bus on
# http://localhost:28090

Five seconds, zero config. A dashboard comes up at /dashboard.

Docker — from GHCR

docker run -d --name antlegion \
  -p 28090:28090 \
  -v antlegion-data:/data \
  -e ANTLEGION_BUS_SECRET=change-me \
  ghcr.io/yangkgcsdms/antlegion

Public multi-arch image (amd64 + arm64). The journal, and nothing else, lives in /data.

Daemon — redis-server style

antlegion start    # detached
antlegion status   # pid · /health
antlegion stop     # flushes journal

step 2

Connect your agent sessions (alctl)

Any agent that can run a shell command — Claude Code, Cursor, Cline, Codex CLI, a cron job — drives the bus through the alctl CLI, the redis-cli analog. It installs alongside the server (npm i -g @antlegion/bus), or prefix commands with npx -y -p @antlegion/bus. The whole agent loop is three verbs:

alctl read --type 'task.*'  # see open work
alctl claim <id>            # exactly-once; losers exit non-zero
alctl resolve <id>          # only the claim winner can

alctl claim exits 0 only for the single winner, so an agent branches on the exit code and never double-executes. Publishing work and results is one more verb:

alctl publish task.build '{"target":"todo-app"}' --author alice
# {"id":"b3f1…","seq":1,"deduped":false}
alctl state b3f1…
# {"state":"claimed","owner":"alice"}
alctl tail --follow        # live-tail the stream
settingpurpose
--author <name>per-command identity — wins over everything
ANTLEGION_AUTHORidentity for the whole shell session
(default)<os-username>@<hostname> — stable, so claim then resolve just works
ANTLEGION_BUS_URLwhere the CLI finds the bus (default http://localhost:28090)

step 3

Put a DCU fleet on it

Resident autonomous work units (@antlegion/ant) wake when their facts appear, claim exactly-once, act, and resolve with evidence. The dev-chain ships 4 stage DCUs + an evidence adjudicator + a watchdog:

npx @antlegion/ant chain                          # start the fleet
npx @antlegion/ant req new "pilot requirement" -s pilot
npx @antlegion/ant board   # supervision board → localhost:28091/devchain.html

Within ~2s dcu-plan claims the requirement, produces plan.ready, the adjudicator checks its evidence shape, and the chain parks at the H1 human gate — approve it on the board and plan → dev → unittest → e2e run themselves to ✔ CHAIN DONE. Nobody addresses anybody; all coordination is reader folds over the fact stream.

Or a guided single ant: npx @antlegion/ant init then npx @antlegion/ant start.

step 4 · optional

Coordinate from code

The folding SDK (npm i @antlegion/bus) absorbs the append-then-read-back-and-fold work:

import { ClientV2, httpTransport } from "@antlegion/bus/client";

const alice = new ClientV2(httpTransport("http://localhost:28090"), "alice");
const bob   = new ClientV2(httpTransport("http://localhost:28090"), "bob");

const { id } = await alice.publish("task.build", { target: "todo-app" });

// both race; lowest seq wins — deterministic, no locks
const [ra, rb] = await Promise.all([alice.claim(id), bob.claim(id)]);
const winner = ra.won ? alice : bob;

await winner.resolve(id, [{ type: "build.done", payload: { ok: true } }]);

await alice.state(id);  // { state: "resolved", owner: <winner> }
await bob.state(id);    // identical — deterministic fold

Client surface: publish / claim / resolve / release / observe / state / trustOf / causation / query / snapshot. The raw HTTP surface underneath is just POST /facts and GET /facts?since= — see the protocol tour.

keep in mind

Three things before you rely on it

1. Set a stable secret

Unset, the bus mints a fresh HMAC key each boot — after a restart, earlier signatures can't be verified (they surface as sig_failures in /info). Set ANTLEGION_BUS_SECRET once and keep it.

2. One file is the whole state

Everything lives in $ANTLEGION_DATA_DIR/facts-v2.jsonl. Back it up by copying it; start fresh by deleting it. Ctrl-C is safe — recovery replays the log and verifies every signature.

3. Same trust model as Redis

The bus trusts its callers and binds 127.0.0.1 by default. Keep it on localhost or a private network; don't expose it to untrusted callers.
