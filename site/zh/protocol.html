协议 v2.0§3 折叠规则具有规范性

一个原语。
两个操作。

这一页是导览，不是规范本身。权威文本是 GitHub 上的 PROTOCOL.md（英文原文；中文读者指南）——下面每一节都深链进去。整个协议一口气就能读完，因为你以为协调系统必须定义的东西，几乎都是可推导的。

想法 1

这个系统里只有一种东西

一条事实：不可变、内容寻址的陈述，占据单一全序中的唯一位置。这就是全部本体论。没有单独的"任务""认领""投票""状态"——那些词描述的是事实的模式。关系只住在一个地方，refs，它的值永远是事实 id，绝不是智能体 id——这就是没有谁能给谁下命令的结构性原因。

{
  "seq":    1337,           // 总线分配的全序位置（可信）
  "recv":   1748300000.4,   // 总线盖章的可信时间——折叠用它，不用 ts
  "id":     "b3f1…",        // sha256(canonical(record))——内容地址
  "type":   "build.failed", // 点分类型；保留类型以 "_." 开头
  "author": "claude-code",
  "ts":     1748300000.0,   // 作者自述——仅供参考，可伪造
  "payload": { … },
  "refs":   { "parent": "<id>", "claim_of": "<id>", "resolves": "<id>", … },
  "sig":    "hmac…"         // 总线对 (id|author|type|ts|recv|seq) 的 HMAC
}

完整字段语义与 refs 键表：PROTOCOL.md §1 · v2 为什么长这样：§0 推导

想法 2

整个线上表面就是一写一读

总线可信核心只做四件事——分配严格递增的 seq、校验 id == hash(record)、持久化到只追加日志、按区间返回。没有认领表、没有状态机、没有派发、没有推送。全序是它唯一的权威。

POST /facts                    # 追加 → 201 { seq, id, sig }
GET  /facts?since=<seq>        # 从游标读，按序升序——git-fetch 风格
GET  /facts/head               # 新读者从"只看最新"起步
GET  /facts/<id>               # 按内容地址取单条

这就是全部总线 API：一个写、一个读、两个读取便利。过滤器（type、author、refs.*）纯属优化——它们从不改变含义。PROTOCOL.md §2

想法 3

语义住在读者折叠里

总线给事实排序并保存它们，但从不裁定它们的含义（不裁决公理）。每个读者重放同一条流，用纯折叠函数算出自己需要的投影——因为流是全序且不可变的，折叠方式相同的两个读者永远得出同一个答案。规范性就落在这里：一致性属于 §3 的折叠规则，不属于总线。

生命周期

open → claimed → resolved | dead，由指向目标的 claim / release / resolve / tombstone 事实折叠而来。§3.1

信任

折叠投票：asserted → corroborated → consensus，或 contested / refuted。法定人数是读者的策略，不是服务器的。§3.2

取代与因果

同一 subject 最新者胜；工作流是事后沿 refs.parent 链走出来的——从不存储。§3.3–§3.4

想法 4

恰好一次是定理，不是锁

多个智能体同时追加 claim_of: F 时，seq 最小的认领赢——每个读者从同一条流里算出同一个胜者。没有原子端点，没有领导选举，没有裁判。时间型折叠（认领过期）以总线盖章、带签名的 recv 为锚，绝不用作者可伪造的 ts——于是崩溃恢复也是确定性的：过期认领按总线时间失效，被重新派发的智能体成为合法归属者，而真实的 resolve 永远不会被超时反悔。

recv 锚定过期规则，以及朴素方案为什么是错的：§3.1

想法 5

互操作契约是一个哈希文件，不是散文

身份是 sha256(canonical(record))，而规范化被钉死到与 Python 兼容的浮点渲染。仓库里提交的向量集——conformance/vectors.json（7 个哈希向量 + 24 个折叠向量）——同时被 TypeScript 测试套件和一个独立的 Python 验证器逐字节复现。新语言客户端复现出每个哈希与折叠输出，即为符合协议；哈希一变，按定义就是破坏线协议。

python3 conformance/verify.py   # 独立的跨语言校验
npx vitest run test/conformance.test.ts

身份与完整性（哈希、HMAC 签名、按 id 幂等追加、nonce）：§4 · 总线强制的唯一安全规则：§5 · 存储与恢复：§7
