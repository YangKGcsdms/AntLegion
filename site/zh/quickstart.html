第 1 步

起总线——三种方式任选

总线是一个进程，只做一件事：给每条事实编号、永不擦除。三条渠道跑的是同一个东西，都在 localhost:28090。

npx — 最快

npx @antlegion/bus
# append-only fact bus on
# http://localhost:28090

五秒，零配置。控制台在 /dashboard。

Docker — 从 GHCR 拉

docker run -d --name antlegion \
  -p 28090:28090 \
  -v antlegion-data:/data \
  -e ANTLEGION_BUS_SECRET=change-me \
  ghcr.io/yangkgcsdms/antlegion

公开多架构镜像（amd64 + arm64）。/data 里只有日志文件，别无其他。

守护进程 — redis-server 式

npm i -g @antlegion/bus
antlegion start    # 后台运行
antlegion status   # pid · /health
antlegion stop     # 退出前刷盘

pidfile 与日志随数据目录存放。

第 2 步

把你的智能体会话接进来（alctl）

任何能执行 shell 命令的智能体——Claude Code、Cursor、Cline、Codex CLI、cron 任务——都通过 alctl CLI（redis-cli 的对应物）驱动总线。它随服务端一起安装（npm i -g @antlegion/bus），或给每条命令加 npx -y -p @antlegion/bus 前缀。整个智能体循环就三个动词：

alctl read --type 'task.*'  # 看有哪些开放任务
alctl claim <id>            # 恰好一次；输家退出码非 0
alctl resolve <id>          # 只有胜者能解决

alctl claim 只对唯一的胜者返回 0，智能体据退出码分支，永不双执行。发布工作与结果再加一个动词：

alctl publish task.build '{"target":"todo-app"}' --author alice
# {"id":"b3f1…","seq":1,"deduped":false}
alctl state b3f1…
# {"state":"claimed","owner":"alice"}
alctl tail --follow        # 实时跟流
设置用途
--author <name>单条命令的身份——优先级最高
ANTLEGION_AUTHOR整个 shell 会话的身份
（默认）<os-username>@<hostname>——跨命令稳定，先 claim 后 resolve 直接可用
ANTLEGION_BUS_URLCLI 找总线的地址（默认 http://localhost:28090）

完整智能体指南——动词 ↔ 折叠对照、首条提示词、CLAUDE.md / .cursorrules 规则片段、崩溃恢复：docs/AGENT-CLI.zh-CN.md

第 3 步

放一支 DCU 蚁群上去

常驻的自治工作单元（@antlegion/ant）在自己关心的事实出现时醒来、恰好一次认领、干活、带证据解决。dev-chain 自带 4 个阶段 DCU + 证据裁决器 + 看门狗：

npx @antlegion/ant chain                          # 起蚁群
npx @antlegion/ant req new "试点需求" -s pilot
npx @antlegion/ant board   # 监督看板 → localhost:28091/devchain.html

约 2 秒内 dcu-plan 认领需求、产出 plan.ready，裁决器核查其证据形状，链条停在 H1 人工闸门——在看板上批准，plan → dev → unittest → e2e 自动跑到 ✔ CHAIN DONE。没有谁给谁下命令；全部协调都是事实流上的读者折叠。

或者问答式配置一只工蚁：npx @antlegion/ant init，然后 npx @antlegion/ant start。

第 4 步 · 可选

从代码协作

折叠 SDK（npm i @antlegion/bus）替你消化"追加后读回再折叠"的工作：

import { ClientV2, httpTransport } from "@antlegion/bus/client";

const alice = new ClientV2(httpTransport("http://localhost:28090"), "alice");
const bob   = new ClientV2(httpTransport("http://localhost:28090"), "bob");

const { id } = await alice.publish("task.build", { target: "todo-app" });

// 两边竞速；seq 最小者赢——确定性，无锁
const [ra, rb] = await Promise.all([alice.claim(id), bob.claim(id)]);
const winner = ra.won ? alice : bob;

await winner.resolve(id, [{ type: "build.done", payload: { ok: true } }]);

await alice.state(id);  // { state: "resolved", owner: <winner> }
await bob.state(id);    // 完全一致——确定性折叠

客户端表面：publish / claim / resolve / release / observe / state / trustOf / causation / query / snapshot。底下的原始 HTTP 表面只有 POST /facts 和 GET /facts?since=——见协议导览。

依赖它之前

先记住三件事

1. 设一个稳定的 secret

不设的话，总线每次启动都铸一把新 HMAC 密钥——重启后先前的签名无法验证（在 /info 里以 sig_failures 浮现）。设一次 ANTLEGION_BUS_SECRET，一直用它。

2. 全部状态就是一个文件

一切都在 $ANTLEGION_DATA_DIR/facts-v2.jsonl 里。备份 = 复制它；重来 = 删掉它。Ctrl-C 是安全的——恢复时重放日志并逐条验签。

3. 与 Redis 同款信任模型

总线信任它的调用方，默认只监听 127.0.0.1。留在 localhost 或私有网络里，别暴露给不受信的调用方。
