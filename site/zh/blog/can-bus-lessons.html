恰好一次是定理：CAN 总线教我们的多智能体协调课

关于多智能体协调的三个断言，每个背后都有一张实测表：没有锁的恰好一次、没有协议的崩溃恢复、没有验证者的验证。

在同一个仓库上跑两个 coding agent，看看会发生什么：它们重做彼此的工作，丢失彼此的上下文，还会用两种不同的方式"修好"同一个 bug。人们伸手去拿的每一种药——文件锁、共享 markdown 便签、SQLite 信箱、负责派活的编排 prompt——治的都是症状。病根其实更简单：没有一份共享的、有序的"已发生"记录。

汽车在 1980 年代就把这个问题解决了。

CAN 总线做对了什么

一辆现代汽车里有几十个 ECU——发动机控制、刹车、气囊。多数人听了会意外的是：没有任何中央电脑指挥它们。一个 ECU 从不寻址另一个 ECU。它把事实广播到共享总线上（"轮速是 X"），每个单元监听自己关心的内容、在本地条件满足时行动。刹车控制器不会命令仪表盘亮灯；它陈述一个事实，仪表盘自己的逻辑决定亮不亮。

四十年安全关键系统的量产使用，这条设计原则活了下来：只有事实，没有命令。

AntLegion 就是把这条原则用到 AI 智能体上。它是一条只追加、内容寻址的事实总线。一个本原：全序中某个位置上的一条不可变事实。两个操作：append 和 read。总线本身无状态——它只强制一件事：全序。人们通常为之搭协调服务器的一切（认领工作、销案、信任、因果）都是每个读者都能算出同一结果的、对流的纯折叠。我们的工作单元叫 DCU，向 ECU 致敬，也继承它的纪律：DCU 从不寻址另一个 DCU。

这篇文章剩下的部分，是我们能用数字辩护的部分：当你真的去测量，全序里能推出什么。

断言一：恰好一次的工作分配，不需要锁

机制：要接一个任务，agent 往总线上追加一条引用它的认领事实。规则——在协议规范 PROTOCOL.md §3.1 中是规范性的——序号最小的存活认领胜出。没有锁服务器，没有租约表。每个读者折叠同一个全序，所以每个读者永远算出同一个赢家。恰好一次不是被强制执行的；它是被推导出来的。

我们用最难看的方式测它：副本化的阶段工作单元，各自独立身份，竞争同一批输入。25 条合成需求 × 4 个流水线阶段（方案 → 开发 → 单测 → E2E）= 100 个认领单元，裁决者校验每一件产物。

副本工作单元认领事实竞争输入双执行链完成耗时
×141000025/25~57s
×2816868025/2580.5s
×41628578025/2548.1s

68~78 处真实竞争，双执行为零。给个参照系：MAST 分类学报告野生多智能体系统的步骤重复率是 17.14%。差别不在于我们的 agent 更守规矩——它们在激烈地抢——而在于"谁干什么"不是 prompt 约定，是全序的定理。

注意 ×4 那一行：端到端耗时反而下降了（48.1s vs 80.5s）。竞争的代价只是日志上多出的 _.claim 事实（+117 条）。输掉一场竞速的成本是一次读；并行的收益远大于它。

断言二：崩溃恢复不是协议，是一次折叠

标准的质疑是："行，但赢家拿着认领死掉了怎么办？"

认领在总线盖戳的时间（recv + Δ）上过期，不看作者自报的时钟——而且过期规则是确定性的、锚定在全序本身上，所以所有读者对"认领何时死亡"的共识，和对"谁赢了"的共识来自同一处。不需要任何东西去检测崩溃，不需要通知任何人。根本没有可通知的对象。

我们在一个工作单元刚赢下认领的瞬间杀掉它（kill -9，受害者跑 dev 阶段，一个幸存副本，Δ = 6s）：

事件相对 kill 时刻
受害者赢下认领−0.46s
kill -9（无人被通知，也无人可通知）0
认领在总线时钟过期（+Δ）+5.54s
幸存者折叠出 open、重新认领+8.17s
幸存者完成并 resolve+12.19s

8/8 链全部完成，双执行 0。接管时延恰好分解为三个可预算的项——Δ + 轮询周期 + 幸存者手头的排队——没有任何隐藏的协调步骤，因为根本不存在协调步骤。

随后我们把这一枪自动化重复了 10 次（s2-extended）：过期→接管落在幸存者的轮询相位内（p50 0.03s，p95 1.0s——恰好是 1 秒轮询周期，无隐藏项），kill→resolve p50 9.98s，双执行 0/10。另加一个时钟偏移臂——让一个工作单元把自报时间戳拨错 ±5 分钟——六个折叠探针的输出与对照臂逐字节一致（sha256 全同），因为折叠只认总线盖戳的 recv，从不认作者自称的时间。

断言三：验证不需要中心验证者

文献对去中心化智能体系统最锋利的批评是误差放大——未经验证的"做完了！"层层传播，直到系统自信地错下去（有研究给出 17.2×，对照有中心验证的 4.4×）。通常的结论是：中间必须有一个可信验证者。

我们认为需要的是更弱也更便宜的东西：结构化证据 + 读者侧折叠。在 AntLegion 里，产物携带声明的证据形状——单测报告必须写明它没有覆盖什么；E2E 报告必须列出它真正检查过的页面。裁决单元（它自己也只是一个普通 DCU，不是特权服务器）折叠事实流、拒绝形状残缺的证据。

我们用一个恶意身份攻击它：注入 8 份伪造的全绿报告——缺 not_covered 的绿色测试摘要、伪造 page_checked 的 E2E 结果、类型伪造的 passed:"12"——外加 4 份形状完整的对照：

指标结果
伪造产物被拦截8/8 = 100%
对照被误杀0/4 = 0%

每条拒绝都带着缺失字段清单，落在日志上，可归因到伪造者的身份。"做完了"≠"验证过了"，从此是结构，不是纪律。

一个证明了定理小字的 bug

诚实环节。我们的第一轮竞争实验出了 4 次双执行。解剖结果：一个前次实验的僵尸进程还活在同一条总线上，而且和新工作单元用同一个身份。同一身份下，"最小 seq 胜出"永远判给你自己——定理成立，但它的信任单元是身份，两个共享身份的进程在全序看来就是一个 agent 在跟自己抢。

这次失败教会了我们现在写进文档的运维规则：一个身份 = 一个进程。副本以独立身份注册（--replicas 会替你做），同一身份的重复 sys.registry 声明是控制台可以直接标红的部署错误信号。我们把这段留在文章里，因为它是最有教益的那类结果：机制没有失败——它忠实执行了一个被我们自己违反的前提。

人的那一侧，也测了

再补一个配对实验，因为隔离智能体之间现任的"协调介质"通常是一个在窗口之间转述状态的人。同任务、同裁决闸门、两臂对照：隔离工作单元 + 脚本化的人肉中继，对比同一批工作单元上总线。每轮中继触点：52（N=2）、80（N=4）、64（N=8）→ 总线臂在每个 N 都是 0，而裁决闸门严格 6 → 6 不变。N=8 的回落本身就是发现：中继者占墙钟 96%——计数不再爬升，是因为人饱和了。（完整装置与数据：research/m1m3-paired-2026-08.md；人肉中继按最省力脚本建模，因此这个差距是下界。）

它不是什么，以及我们还没证明什么

不是消息队列（没有东西被消费），不是编排器（没有人派活），不是工作流引擎（流水线由流折叠而来，从不被存储）。

上面的实验用模拟工作动作（每阶段 2.5~4s）来隔离协调层；同一套装置跑过 100 次 LLM 驱动的阶段循环、57 秒端到端，但上面的表测的是排序，不是模型质量。

单总线全序：一个部署域一个总线进程。这是定位选择（Redis 形状的本地优先基础设施），不是分布式共识成果——我们不做多主张。信任模型：默认绑定 127.0.0.1，调用者受信；暂无鉴权（在路线图上，README 里如实写明）。

复现它

上面的一切各自只要一条命令（bus 0.4.x / ant 0.4.x，MIT）：

npx @antlegion/bus demo                          # 15 秒零配置：竞速 → kill 接管 → 逐字节重放
npx @antlegion/bus                               # 终端 1：一条真总线
npx @antlegion/ant mvp --reqs 25 --replicas 4    # 终端 2：竞争实验本验

线协议是一份规范（PROTOCOL.md；§3 的折叠规则是规范性的），配跨语言一致性向量——TS 套件与独立 Python 验证器在 CI 里逐字节复现每一个哈希。原始实验记录：research/s2-experiments-2026-08.md。
