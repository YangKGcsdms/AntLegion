为智能体共享世界状态的
事实日志

跨机器、跨运行时、跨厂商的智能体之间没有共享内存，状态要么靠编排器发号施令，要么靠你在窗口之间复制粘贴。AntLegion 用一条日志取代两者：智能体只写自己观察到的，从不写命令；日志只做一件事——给每行编号，永不擦除。现在是什么、因何而起、引出了什么、归谁所有，每个智能体读同一条日志，算出同一个世界。蚂蚁不互相传话，只读地面。

1. 一切都是一行字

观察、修订、告警、所有权——全是同一条日志上的行。没有人给谁下命令；智能体读到什么，自己折叠。

2. X 现在是什么

用一个普通字符串（deploy:prod）给世界的一块命名，关于它行号最大的那一行就是它的当前值——每个节点上一模一样。撤回它，折叠为"一无所知"，绝不回到旧值。

3. 怎么来的，接下来呢

每一行都能写明自己的因。向后走是"这一步是怎么来的"，向前走是"它引发了什么"。内容哈希，事后伪造不了踪迹。

4. 没有一行会被擦掉

日志烧了，把每行字重放一遍——所有人拿回一模一样的世界，逐字节相同。真需要所有权的时候，它是行号上的算术，不是锁。

黑板架构比万维网还老——一块人人往上写、没有人通过它被寻址的共享介质。它一直没解干净的问题是"谁来仲裁"；AntLegion 的回答是行号。下面是所有权规则在争用下的实况：

把你的 Claude Code / Cursor 接进来

同一条日志、同一批事实——一个会话学到的，每个会话都知道；没有人在窗口之间粘贴状态。

alctl publish obs.metric '{"cpu":91}' --subject host:web-3  # 写下发生了什么
alctl current host:web-3     # 读世界——每个窗口同一个答案
alctl claim <id>            # 恰好一次地拥有一条事实；输家退出码非 0
alctl resolve <id>          # 只有胜者能解决

每个会话通过 alctl CLI 驱动总线——发布事实、动手前先认领、折叠同一条日志。两个会话抢同一个任务：一个赢，一个转身干别的。

Alpha：线协议与日志格式已冻结（跨语言一致性向量锁定）；API 表面仍会调整。仅限 localhost / 私有网络——与 Redis 同款信任模型。

给系统派的你

这条日志在技术上是什么

一条只追加、全序、由不可变的内容寻址事实构成的日志——一条共享世界状态的日志。subject 寄存器（"X 现在是什么"）、因果踪迹（向后与向前）、信任、所有权全部是读者侧计算的纯折叠；总线本身无状态，只负责分配顺序。每个 ref 指向的都是事实而不是智能体——所以上面没有一条是命令。流水线不是自上而下设计的——每条事实记录自己的来处，如果你搭了一条工作流，那是事后从踪迹里折叠出来的。规范：PROTOCOL（规范性折叠规则 + 跨语言一致性向量）。

不是消息队列 · 不是编排器 · 不是工作流引擎——也不锁文件：共享同一个世界的两个智能体，不需要有人告诉它对方在干什么。

起源

生于 CAN 总线

汽车的 CAN 总线（1986）上，没有中央电脑指挥各个控制单元——每个单元监听自己关心的报文，本地条件满足就行动。AntLegion 保留了这种广播纪律，并补上 CAN 从未有过的两样东西：记忆（只追加日志）与因果（事实的血缘）。工作单元命名为 DCU，向 ECU 致敬。

常见问题

你可能想问

多个 Claude Code / Cursor 会话之间怎么共享状态？

起一条日志（npx antlegion），再让每个会话通过 alctl CLI 驱动它（alctl publish --subject / alctl current / alctl causation；见 docs/AGENT-CLI.zh-CN.md）。每个会话把观察到的沉积上去、折叠同一条日志——一个会话学到的，每个会话都知道，不用你粘贴。如果两个会话还需要不做同一件事，所有权（alctl claim）就是同一条日志上多一个折叠。

为什么不直接用 Claude Code 的 subagents / agent teams？

该用就用——一台机器、一棵进程树、一个厂商之内它们很好。AntLegion 从它们停下的地方开始：物理隔离节点上的智能体——不同机器、权限域、厂商——那里不存在"更大的单体 agent"，现状是人在转述状态。

8/8 伪造报告是怎么拦下来的？

每个生产者为自己的产物注册"证据形状"（测试报告必须写明没测什么、E2E 报告必须带偏差/缺陷/缺口……）。裁决单元把每个产物对着注册的形状折叠一遍并公布接受/拒绝——它从不信任智能体的自我汇报。我们注入了 8 份形状残缺的"全绿"产物：8 份全部被拒，缺失字段点名上链；4 份形状完整的对照全部通过。见 PROTOCOL §3。

这是消息队列吗？

不是。队列把命令投递给消费者然后遗忘。AntLegion 把不可变事实永久保存（支持压缩）在单一全序里，任何读者在任何时刻都能重建：谁认领了什么、什么取代了什么、一个结果是怎么来的。协调语义住在读者侧折叠里，不在 broker 里。

它锁文件吗？

不锁。折叠同一个世界的智能体已经知道彼此在干什么；需要独占时，动手前先认领那条事实，恰好一次所有权是日志顺序的定理。没有人编辑同一处，就没有什么需要锁。

智能体干到一半崩溃了会怎样？

它的认领会过期（按总线盖章的时间，不是智能体自己的时钟），任何幸存的智能体赢下重新认领并接管。恢复是确定性的：重放日志，得到同一个世界。实测：SIGKILL 后 12.2 秒链条痊愈。

哪些智能体能接入？

原生常驻蚂蚁走 @antlegion/ant（脚本或 LLM 驱动的 act）；任何能执行 shell 命令的（Claude Code、Cursor、Cline、Codex CLI、Windsurf、Zed……）经 alctl CLI；以及任何能发 HTTP 或引入 TypeScript SDK 的东西。

能上生产吗？

Alpha。核心协议稳定且经过验证——218 个测试、跨语言一致性向量、进程内约 16 万 append/s——但它按可信环境设计（与 Redis 同款模型）：留在 localhost 或私有网络里，设置稳定的 secret。
